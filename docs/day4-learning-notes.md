# 📓 Day 4 학습 노트: Framer Motion 레트로 애니메이션과 상태 트리거 최적화

Day 4에서 Framer Motion을 활용한 픽셀 아트 모달 및 Confetti 애니메이션을 구현하고, 상태 변화의 멱등성 버그를 해결하며 학습한 핵심 개념들을 정리한 문서입니다.

---

## 1. Framer Motion `AnimatePresence`와 퇴장(Exit) 애니메이션

### ❓ 왜 필요한가?
React의 조건부 렌더링(`{isLeveledUp && <Modal />}`)은 조건이 거짓이 되는 순간 컴포넌트를 DOM에서 즉각 삭제합니다. 이로 인해 컴포넌트가 사라질 때의 전환 효과(Fade-out, Scale-down 등)를 주는 것이 불가능합니다.

### 💡 해결 원리
* `AnimatePresence` 컴포넌트로 조건부 렌더링 영역을 감쌉니다.
* 내부 자식 컴포넌트(`motion.div`)에 `exit` 속성(예: `exit={{ opacity: 0, scale: 0.8 }}`)을 설정합니다.
* 컴포넌트가 언마운트되는 순간, `AnimatePresence`가 실제 DOM 삭제를 일시 지연시키고 `exit` 애니메이션이 끝난 후에 안전하게 요소를 제거합니다.

---

## 2. React 상태의 멱등성(Idempotency)과 카운터 트리거 패턴

### 🚨 문제 상황 (Boolean 트리거의 한계)
* 습관 완료 시 터지는 파티클을 켜기 위해 `showConfetti`를 `boolean`(`true`/`false`)으로 관리했을 때 발생한 버그입니다.
* 첫 번째 클릭 시 `true`가 된 상태에서, 1.2초의 애니메이션이 다 끝나기 전에 두 번째 클릭을 하면 상태가 여전히 `true`로 갱신을 시도합니다.
* React 엔진은 이전 상태와 동일한 값(`true ➡️ true`)이 들어오면 컴포넌트 재렌더링 및 `useEffect` 트리거를 수행하지 않아 연속 클릭 시 파티클이 씹히는 버그가 유발됩니다.

### 🛠️ 해결 (Counter Trigger Pattern)
* 트리거 상태를 숫자인 카운터(`confettiTrigger: number`)로 정의합니다.
* 클릭할 때마다 `setConfettiTrigger(prev => prev + 1)`을 실행하여 상태 값을 강제 변경시킵니다 (0 ➡️ 1 ➡️ 2 ➡️ 3...).
* React는 이전 숫자와 새로운 숫자가 다름을 항상 감지하므로 씹히지 않고 매 클릭마다 애니메이션 이펙트를 재실행할 수 있습니다.
* 파티클 상태 생성 시 `id` 값에 `Date.now() + index` 형태의 유일값을 부여해 연속 클릭 시 뿜어지는 파티클들이 브라우저 렌더링 엔진 내에서 고유하게 구분되도록 보장합니다.

## 3. Framer Motion Keyframes 배열을 활용한 중력(포물선) 연출

### 🛸 가벼운 포물선 애니메이션 구현 기법
물리 연산 라이브러리(Velocity, Matter.js 등)를 사용하여 중력 가속도를 계산하지 않고, Framer Motion의 **배열 형태의 값(Keyframes)** 지정을 활용해 브라우저 렌더링에 친화적인 픽셀 조각 낙하 이펙트를 설계했습니다.

* **y축 키프레임:** `y: [0, p.y, p.y + 400]`
  * `0` (시작 위치 - 체크박스 또는 화면 중앙)
  * `p.y` (랜덤한 음수값 - 하늘로 튀어 오르는 지점)
  * `p.y + 400` (양수값 - 바닥으로 수직 낙하하는 중력 시뮬레이션 지점)
* 이처럼 순서대로 바뀌는 경로 배열을 제공함으로써 브라우저에 연산 부담을 주지 않는 가벼운 8-bit 스타일 Confetti를 탄생시켰습니다.
